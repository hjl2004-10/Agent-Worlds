【2026-03-19 更新】提示词系统重构 + MCP 热加载修复
================================================================================

一、功能概述
--------------------------------------------------------------------------------
将提示词字段拆分为「动态工具提示」和「用户额外提示」两个独立字段，
修复 MCP 工具连接后无法使用的 bug，统一 PRESETS 索引机制。

二、详细清单
--------------------------------------------------------------------------------
1. 提示词字段分离
   - 旧: rom_tools_prompt (Skill摘要 和 用户手写内容 混用)
   - 新: rom_tools_prompt = Skill/MCP 动态生成的工具摘要
         rom_extra_prompt = 用户手写的教学/指令文本
   - HJL 字段: tools_prompt → extra_prompt (loader 向后兼容旧字段)
   - 模板变量: {tools_prompt} 保留给动态工具, 新增 {extra_prompt}
   - 前端: "工具提示" 改名为 "额外提示"

2. MCP 工具热加载修复
   - Bug: connect_mcp 成功后, 22 个 MCP 工具写入 mcp_tool_defs,
          但工具循环的 tools 列表是入口快照不会刷新,
          导致 LLM 反复调用 connect_mcp (最多 10 次)
   - 修复: tool_executor 中 connect_mcp 成功后立即追加新工具到
          共享 tools 列表, 下一轮 LLM 调用即可使用

3. PRESETS 索引机制优化
   - 旧: full = [0,1,2,3,4,5,7] (硬编码索引, 新增模板行后错位)
   - 新: full = None (取 rom_prompt 全部模板行, 用户配什么渲染什么)
   - prompt_l1.assemble 支持 indices=None

4. 前端可用变量列表补全
   - 从 10 个补到 15 个, 与 prompt_l2.build_context 一一对应
   - 新增: speaker_name, lore_text, scene_name, scene_desc, memory_note

三、影响范围
--------------------------------------------------------------------------------
后端: body/npc.py, tools/loader_l1.py, core/prompt/prompt.py,
      core/prompt/prompt_l1.py, core/prompt/prompt_l2.py,

================================================================================

一、功能概述
--------------------------------------------------------------------------------
将邮箱图标升级为虚拟电脑图标，实现交互式 HTML 应用的渲染和执行。

核心特性:
  - 邮箱图标 → 💻 虚拟电脑图标
  - 点击打开虚拟电脑界面 (模拟桌面)

--------------------------------------------------------------------------------

   - 支持类型: text, image, document

2. 新增 send_html_mail 工具

   - title (必填): 应用名称 (显示在桌面图标下)

   - device_mode (可选): 设备模式 mobile=390x844 / desktop=800x500

【2026-03-03 更新】NPC 禁用功能
================================================================================

一、功能概述
--------------------------------------------------------------------------------
在 HJL 配置文件中添加 enabled 字段，控制 NPC 是否参与系统活动。

禁用的 NPC:
  - 仍加载到内存 (保留状态、可显示、可热切换)
  - 不参与任何活动 (移动、碰撞、定时器、任务等)
  - 前端显示为半透明 + 灰化状态
  - 头顶显示 [已禁用] 标签

二、数据流
--------------------------------------------------------------------------------
  HJL 文件                     内存                        前端
  ┌──────────────┐            ┌──────────────┐            ┌──────────────┐
  │ enabled: true│ ──加载──> │ npc.enabled  │ ──API───> │ 正常显示     │
  │ enabled: false│           │  = True/False│           │ 半透明/灰化  │
  └──────────────┘            └──────────────┘            └──────────────┘
                                   │
                                   ↓ 过滤
                            ┌──────────────┐
                            │ 驱动层/定时器 │
                            │ 只处理 enabled=True
                            └──────────────┘

三、HJL 文件格式
--------------------------------------------------------------------------------
{
  "attributes": {
    "enabled": true,   // 新增字段，默认 true
    "description": "...",
    ...
  }
}

四、影响范围
--------------------------------------------------------------------------------
| 场景       | 禁用 NPC 的行为                 |
|:----------|:-------------------------------|
| 移动       | 不移动，保持原位                 |
| 碰撞检测   | 不与其他 NPC 触发对话            |
| 被碰撞     | 其他 NPC 不会与禁用 NPC 触发对话  |
| 定时器     | 不响应定时器触发                 |
| 任务       | 不接收/处理任务                  |
| 主动值恢复 | 不恢复                           |
| 前端显示   | 半透明 + 灰化 + [已禁用] 标签     |
| API 返回   | 包含在列表中，enabled: false      |

五、API 端点
--------------------------------------------------------------------------------
GET /api/npcs
  返回数据新增 enabled 字段

GET /api/npc/{npc_name}/config
  返回配置新增 enabled 字段

POST /api/npc/{npc_name}/config
  支持更新 enabled 字段

PATCH /api/npc/{npc_name}/enabled (新增)
  请求体: { "enabled": false }
  功能: 设置 NPC 启用/禁用状态

六、热切换支持
--------------------------------------------------------------------------------
  - 运行时禁用: 调用 API 后立即生效，下个 tick 不再参与活动
  - 运行时启用: 调用 API 后立即生效，下个 tick 恢复活动
  - 持久化: 状态变更时自动保存到 HJL 文件，重启后保持

七、修改文件列表
--------------------------------------------------------------------------------
后端:
  body/npc.py                  新增 self.enabled = True 属性
  tools/loader_l1.py           加载时读取 enabled，保存时写入 enabled
  core/drive/drive_l1.py       入口处过滤 enabled=False 的 NPC
  tools/timer_l1.py            触发前检查 npc.enabled
  main.py                      API 返回 enabled 字段，新增启用/禁用 API

前端:
  static/src/components/Map/MapView.tsx  禁用 NPC 半透明 + 灰化显示

   - 保留 analyzer 模块框架，后续可用于其他属性分析

   - modify_initiative: NPC 调整自己的主动性

三、工具定义
--------------------------------------------------------------------------------
modify_initiative:
  描述: 调整自己的主动性 (正数=更想继续对话，负数=想结束对话)
  参数:
    - delta (integer, 必填): 变化量 (正数增加，负数减少)

  示例: modify_initiative(delta=2, reason="聊得很开心")

modify_others_initiative:
  描述: 调整他人的主动性 (影响对方是否想继续对话)
  参数:
    - target (string, 必填): 目标 NPC 名称
    - delta (integer, 必填): 变化量
    - reason (string, 可选): 原因
  示例: modify_others_initiative(target="Bob", delta=-3, reason="话题无聊")

四、边界限制
--------------------------------------------------------------------------------
主动值范围: -10 到 10
超出范围自动截断到边界值

五、修改文件
--------------------------------------------------------------------------------

【2026-02-25 更新】NPC 导入导出系统
================================================================================

一、功能概述
--------------------------------------------------------------------------------
实现 NPC 导入导出系统，支持：
  - 单个或批量导出 NPC 到 JSON 文件
  - 从 JSON 文件导入 NPC (单个或群组)
  - 导出时保留完整的 HJL 数据格式
  - 导入时可选择覆盖已存在的 NPC

二、导出功能
--------------------------------------------------------------------------------
导出格式 (JSON 文件):
{
  "version": "1.0",
  "type": "NPC_GROUP",
  "exported_at": "2026-02-25T...",
  "npcs": [
    { "header": {...}, "position": {...}, "attributes": {...}, "memory": {...} },
    { "header": {...}, "position": {...}, "attributes": {...}, "memory": {...} }
  ]
}

特点:
  - 导出前自动将 ram_buffer 转换为历史记录格式
  - 保留完整的 NPC 配置 (人设、工具、群组、LLM配置、背包等)
  - 支持多选批量导出
  - 自动生成带日期的文件名

三、导入功能
--------------------------------------------------------------------------------
导入流程:
  1. 选择导出的 JSON 文件
  2. 预览将要导入的 NPC 列表
  3. 显示每个 NPC 是否已存在
  4. 可选"覆盖已存在的 NPC"
  5. 确认导入

导入后:
  - 在后端 data/individuals/ 目录生成对应的 .hjl 文件
  - NPC 自动加载到内存
  - 更新 social_l1 的 NPC 引用

四、API 端点
--------------------------------------------------------------------------------
POST /api/npc/export
  请求: { "names": ["Alice", "Bob", "Charlie"] }
  返回: {
    "status": "ok",
    "exported_count": 3,
    "npcs": [...],

【2026-02-18 更新】goto_location 避障寻路
================================================================================

一、问题描述
--------------------------------------------------------------------------------
NPC 使用 goto_location 前往目标地点时，采用直线移动方式。
当路径上有障碍物时，NPC 会被卡住，无法绕行到达目标。

二、解决方案
--------------------------------------------------------------------------------
重构 move_toward_target() 函数，增加避障绕行逻辑:

  1. 直线移动被阻挡时，检测阻挡的障碍物
  2. 根据障碍物类型 (矩形/圆形) 计算绕行方向
  3. 尝试沿绕行方向移动
  4. 绕行方向也被阻挡时，尝试反方向
  5. 都不行则尝试垂直于目标方向移动
  6. 所有方向都阻挡才保持原位

三、新增避障函数 (env/map_l2.py)
--------------------------------------------------------------------------------
  - get_obstacle_edges(): 获取障碍物边界坐标
  - line_intersects_rect(): 检测线段是否与矩形相交 (Liang-Barsky 算法)
  - find_blocking_obstacle(): 找到阻挡路径的第一个障碍物
  - find_detour_direction(): 根据障碍物类型计算绕行方向

绕行策略:
  - 矩形障碍物: 根据长宽比选择绕行方向
    - 横向墙 (宽>高): 从上下绕
    - 纵向墙 (高>宽): 从左右绕
  - 圆形障碍物: 沿切线方向绕行
    - 选择与目标方向更一致的切线

四、修改文件
--------------------------------------------------------------------------------
  env/map_l2.py              新增避障辅助函数
  core/drive/drive_l2.py     move_toward_target() 增加避障逻辑

     - 相关记忆 < limit: 补充最近的无关记忆
     - 无相关记忆: 取最近 N 条

  2. 无对话对象时:
     - 取最近 N 条记忆 (原有逻辑)

【2026-02-18 更新】记忆格式转换修复
================================================================================

一、问题描述
--------------------------------------------------------------------------------
NPC 的记忆 (hdd_history) 中混入了 JSON 对象格式的数据：
  正常格式: "[1月1日 14:56] 我对Player说: 你好..."
  异常格式: {"role": "assistant", "content": "（从电脑前抬起头..."}

二、问题根源
--------------------------------------------------------------------------------
对话过程中，ram_buffer 存储的是 JSON 格式:
  {"role": "assistant", "content": "..."}  (发言者)
  {"role": "user", "content": "..."}       (听者)

对话正常结束时，finalize_conversation() 会转换为文本格式存入 hdd_history。
但如果对话异常中断（超时/程序崩溃/其他保存路径），JSON 对象会被直接写入 hdd_history。

问题出在两个位置:
  1. tools/loader_l1.py 的 save_npc_to_file()
  2. core/mem/mem_l1.py 的 persist_memory() 和 write_memory()

  def _convert_ram_to_history(ram_buffer):
      converted = []
      for msg in ram_buffer:
          if isinstance(msg, dict):
              # JSON 格式 -> 转换为文本格式
              role = msg.get('role', 'unknown')
              content = msg.get('content', '')
              if role == 'assistant':
                  record = f"[对话中] 我说: {content}"
              else:
                  record = f"[对话中] 对方说: {content}"
              converted.append(record)
          else:
              # 已经是文本格式，直接使用
              converted.append(msg)
      return converted

  - 新坐标 = 当前坐标 + 随机偏移
  - 使用 max/min 限制在地图边界内 [0, max_w] x [0, max_h]

四、迟滞状态机 (Hysteresis) (core/drive/drive_l2.py)
--------------------------------------------------------------------------------
目的: 防止 NPC 在边界距离反复触发/解除对话

双阈值设计:
  - 入阈值 (th_contact = 2.0): 距离 <= 2.0 时触发对话
  - 出阈值 (th_leave = 5.0):   距离 >= 5.0 时解除禁止

状态流转:
  1. 正常状态 (ban_target = None)
     -> 距离 <= 2.0 -> 触发对话 -> 设置 ban_target

  2. 禁止状态 (ban_target = 对方name)
     -> 距离 >= 5.0 -> 解除禁止 -> ban_target = None
     -> 距离 < 5.0  -> 保持禁止，不触发对话

示意图:
  |<--禁止区-->|<--死区-->|<--可触发区-->|
  5.0         2.0        0
  (出阈值)    (入阈值)   (接触)

--------------------------------------------------------------------------------

  阶段0: 主动值恢复 (每50 tick)
  阶段1: 物理移动 (仅非对话 NPC)
  阶段2: 两两遍历检测距离
         -> 调用 check_hysteresis_state() 判定
         -> 分支A: should_talk=True  -> 触发对话
         -> 分支B: should_clear=True -> 解除禁止

功能: NPC 之间可以互相添加任务提醒

文件结构:
  tools/
    ├── task.py        总控层 - 全局任务池、接口定义
    └── task_l1.py     业务层 - 工具处理函数

全局任务池:
  TASK_POOL = {
    "Alice": [task1, task2, ...],
    "Bob": [task3, ...]
  }

任务结构:
  {
    "hint": "去看文件",           # 提示内容
    "source": "David",            # 来源
    "tool_hint": "read_file: ...", # 工具指引 (可选)
    "status": "pending"           # 状态: pending/done
  }

工具:
  - add_task: 给某人添加任务
    参数: target (人名), hint (提示), tool_hint (工具指引)

  - complete_task: 标记任务完成
    参数: hint (模糊匹配)

动态工具注入:
  - 任务携带 tool_hint 字段
  - format_task_tools() 解析需要的工具名
  - 在 NPC 对话时自动注入工具说明
  - 即使 NPC 原本没有该工具提示词，也能知道如何调用

示例流程:
  1. David 调用 add_task(target="Alice", hint="去看文件", tool_hint="read_file: path=letter.txt")
  2. Alice 下次对话时看到:
     - "去看文件" (任务提示)
     - "【可用工具】- read_file: 读取文件内容..." (动态注入)
  3. Alice 调用 read_file 读取文件
  4. Alice 调用 complete_task(hint="文件") 标记完成

并发安全设计:
  - 任务存储在全局 TASK_POOL，而非 NPC.memory
  - 添加任务 → 追加到池 (无竞态)
  - 对话时 → 从池读取 (只读)
  - 完成任务 → 修改池中状态 (单线程)
  - 为后续多 NPC 并发对话做准备

六、多协议工具调用系统
--------------------------------------------------------------------------------
功能: 支持多种工具调用协议，可扩展

文件结构:
  tools/tool/
    ├── tool.py              总控层 - 注册表管理、接口定义
    ├── tool_l1.py           业务层 - 协议路由
    ├── tool_l2.py           原子层 - 通用工具函数
    └── providers/           工具协议适配器
        ├── __init__.py      提供者注册
        ├── base.py          基类定义
        ├── custom.py        自定义文本触发 (【工具:xxx】)
        └── anthropic.py     Anthropic 原生 tool_use

协议类型:
  - custom: AI 回复中包含特定文本触发
    例如: "【工具:测试】", "[group:朋友]"

  - anthropic: API 级别的原生工具调用
    在调用 LLM 时传入 tools 定义，API 返回 tool_use block

内置工具 (Anthropic 协议):
  - read_file: 读取文件内容
  - write_file: 创建/写入文件
  - edit_text: 编辑文件 (replace/insert/delete_range)

注册表结构:
  TOOL_REGISTRY = {
    "custom": { 工具ID: {trigger, handler, ...} },
    "anthropic": { 工具名: {description, input_schema, handler, ...} }
  }

接口:
  - get_anthropic_tool_definitions(): 获取 Anthropic 格式工具定义
  - invoke_custom_async(): 异步调用 custom 协议工具
  - register_tool(protocol, tool_id, config): 动态注册工具
